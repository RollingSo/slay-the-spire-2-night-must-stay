# 卡牌文本与机制实现强制规范

> 本规范适用于所有角色的卡牌代码、中英文本地化、升级文本、生成牌预览与导出前检查。

## 1. 关键词只允许单一来源

- `虚无`、`消耗`、`保留`等原生关键词必须由卡牌代码中的 `CanonicalKeywords`、`AddKeyword` 或 `RemoveKeyword` 驱动。
- 若关键词已由代码声明，卡牌的 `description` 与 `upgradeDescription` 不得再次手写同名关键词；游戏会自动渲染关键词行，手写会造成重复。
- 升级新增或移除关键词时，升级后的规则文本仍应描述完整效果，不得只写“添加保留”“移除消耗”等会与自动关键词行重复的句子。
- 机制正文中引用别的牌或条件时可以提到这些词，例如“使所有虚无牌耗能-1”；这不属于当前牌自身的关键词标注。

## 2. 句子与换行

- 卡牌正文中每个独立句号后一般必须换行，即中文使用 `。\n`，英文使用 `.\n`。
- 最后一句末尾不需要额外空行。
- 只有同一句内部的并列短语、数值范围、括号动态预览或必须保持一行的短机制标签可以不拆行。
- `description` 与完整句式的 `upgradeDescription` 都要遵循此规则。

## 3. 机制词高亮

- 项目自定义机制名在卡牌正文中使用 `[gold]...[/gold]`，包括但不限于`蓄力`、`回收`、`共鸣`、`呼唤`、`冻伤`、`标记`。
- 同一机制在基础文本、升级文本以及中英文文本中的高亮方式必须一致。

## 4. 生成牌与升级预览

- 文本若明确生成升级牌，牌名必须显示 `+`，例如`接近+`、`远离+`。
- 实际生成逻辑必须在加入牌堆前完成升级。
- 悬停预览必须展示升级版本，使用支持升级参数的接口，例如 `HoverTipFactory.FromCardWithCardHoverTips<T>(true)`。
- 卡面文本、悬停预览和实际生成结果三者必须一致。

## 5. 双语与导出检查

- 修改中文卡牌正文时同步检查英文正文，反之亦然。
- 任何卡牌机制、数值、耗能、目标、关键词或升级效果发生修改时，必须在同一轮修改中同步核对并更新卡牌代码、`description`、`upgradeDescription`、动态数值、关键词行、额外解释框与升级预览；不得出现机制已经生效但卡面文本或升级文本仍为旧版本的情况。
- 升级新增关键词时，必须同时确认升级后的实际卡牌和升级预览均会显示对应的原生关键词行，不能只修改 `CanonicalKeywords`、只修改 `OnUpgrade` 或只修改本地化文本后便视为完成。
- 修改后运行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/validate_card_text_format.ps1
```

- 检查不通过时不得导出或替换 Mods。
