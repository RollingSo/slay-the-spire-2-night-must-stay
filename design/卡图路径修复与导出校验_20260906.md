# 卡图路径修复与导出校验

## 问题与修复

2026-09-06 本机日志 `godot.log` 明确报告 `evolution_wings.png`、`storm_barrier.png`、`heavy_halberd.png` 加载失败。32 个守护者 PortraitPath 使用 `ImageHelper.GetImagePath("packed/card_portraits/guardian/...")`，该帮助函数会额外添加 `images/` 前缀。

实际受 Git 管理并导出的卡图位于 `res://packed/card_portraits/guardian/`，已有卡图 AtlasTexture 也引用这里。`images/packed/card_portraits/guardian/` 并不存在，且是项目明确忽略的旧重复目录。

修复将上述 32 处直接指向规范的 `res://packed/card_portraits/guardian/*.png`；不制造第二份镜像，不重绘守护者卡图，不修改卡牌机制或文本。

## 防止复发

正常导出现在执行两层检查：

1. `tools/validate_card_portraits.ps1` 收集卡牌显式路径、ImageHelper 实际解析路径、各角色正式卡图目录与卡图 atlas 依赖，任何源路径缺失即失败。生成构建专用路径清单，不修改卡表。
2. Godot 完成 PCK 导出后，从独立的 `tools/card_portrait_validation` 项目挂载新包，逐项用 ResourceLoader 加载 Texture2D 并解码图像。独立目录没有源图与主项目导入缓存，不会将「源码可读取」误判为「PCK 已打包」。失败会阻止后续安装。

本地含其他开发内容的测试包检查：488 个卡图/atlas 资源，失败 0；Release 构建 0 警告、0 错误。此为资源与导出验证，不冒称完整游戏实战验收。
