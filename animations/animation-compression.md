# 动画压缩与 Mod 导出

更新日期 2026-11-10。适用于 `animations/<角色>/main/` 和 `derived/` 下的运行时资源。素材布局见 [animate.md](animate.md)，动作时间与接入要求见[角色战斗动画制作与 Mod 适配工作流](../design/角色战斗动画制作与Mod适配工作流.md)。

**目标是在保持游戏内画质和动作表现的前提下，让 PCK 尽可能小。** 保留已采纳的 RGBA 母版和原始时间线，每次从同一份母版生成发布候选。先用无需改动画画面的方式减重，再对大资源逐个比较有损候选。默认保留原帧数、逐帧时长、画布、锚点和最终可见体型。

## 1. 先清理导出范围

1. 用同一份代码和同一个 Godot 版本导出基线，记录 PCK 总字节数。检查实际包内条目。Godot 会重映射场景、资源和导入纹理，包内大小应以实际 `.res`、`.ctex` 等条目为准。
2. 生产动作只保留一条运行路径。迁移场景、GDScript `load`／`preload`、C# `GD.Load`、资源预热和回退路径后，再排除对应旧副本。文件名相同的两份资源先比较内容和运行用途，旧版本可能仍承担回退。
3. 在 [export_presets.cfg](../export_presets.cfg) 中排除 `preview/`、绿幕首帧、候选图集和制作中间文件。当前 `export_filter="all_resources"` 会扫描可导出的资源，`include_filter` 不充当资源白名单。切换到选择性导出时，显式覆盖动态加载的资源及其依赖。
4. 检查单个 `SpriteFrames` 内的动画列表。经确认弃用、且没有引用的备选动作可从发布版移除。女爵 DU09 的人物和表盘各保留原速动作，均为 121 帧、约 5.017 秒。两层继续使用同一播放时钟，已弃用的 1.458 秒短版可从两份发布资源中移除。

## 2. 优先做无损优化

| 做法 | 实施要求 |
|---|---|
| 复用完全相同的帧 | 只有像素及绘制偏移等价时才共用纹理或图集区域。保留各帧在 `SpriteFrames` 中的索引与时长，释放点和事件仍指向原时间线。 |
| 减少透明空白和空图集页 | 用所有帧的可见边界并集加安全边距裁切，补偿裁切原点，保留脚底、武器尖端和半透明特效。保留图集区域间距，检查纹理过滤时相邻帧是否串色。 |
| 比较无损编码 | 对嵌入式图集试 `PortableCompressedTexture2D` 的 `COMPRESSION_MODE_LOSSLESS`。外置图集走 Godot `Lossless` 导入，比较导出结果。逐帧校验可见 RGBA 和显示尺寸后再选体积更小的版本。 |

关闭 mipmap、缩小分辨率和降低采样率都需要单独评估实际显示效果。初次压缩沿用母版分辨率和帧数。需要进一步缩小时，先确认游戏内可见像素尺寸和最大显示缩放，再单独出候选。待机循环须检查接缝，攻击须检查起手、释放、命中和收招。

## 3. 按动作选择有损压缩

无损版本仍偏大时，从体积最大的图集开始。先对比 `0.95` 和 `0.90`，画面通过后再试 `0.85` 等更低档位。每档都从同一母版重新编码，选择通过验收的最小版本。`0.85` 是当前测试档位，各动作可以选不同质量。细武器、羽毛、蓝白灵体、透明表盘和高反差轮廓优先保画质，有可见退化就提高质量或采用无损。

- **嵌入图集的 `.res`。** 遍历 `SpriteFrames` 的帧纹理，每张不同的底层纹理只编码一次。用 `PortableCompressedTexture2D` 的 `COMPRESSION_MODE_LOSSY`，在 `create_from_image()` 前设置 `keep_compressed_buffer = true`。保留 `AtlasTexture` 的区域、边距、`filter_clip`，以及资源里的动画名、帧序、时长、元数据和尺寸。保存 `.res` 后在新进程重载。
- **外置图集的 `.tres`。** 保持正式图集输入与引用，在 Godot 导入设置中对指定图集选择 `Lossy` 和质量档位，重新导入后比较导出的 `.ctex`。只调整动作图集的设置。
- **下载体积和显存分别验收。** Lossy WebP 主要减少磁盘和下载体积，通常不会降低解码后纹理的显存占用。长循环可按商店、篝火和战斗场景分别加载。显存仍偏大时，再测裁切、图集页大小与加载时机。

引擎参考见 [Godot 4.5 图像导入](https://docs.godotengine.org/en/4.5/tutorials/assets_pipeline/importing_images.html)和 [PortableCompressedTexture2D](https://docs.godotengine.org/en/4.5/classes/class_portablecompressedtexture2d.html)。

## 4. 画质与发布验收

1. **逐帧对比。** 在实际游戏尺寸及最大支持显示缩放下，用相同位置、过滤设置和背景并排看母版与候选。检查浅色、深色及典型战斗背景，重点看武器尖端、半透明边缘、羽翼、暗部和细高光。放大定位色块、色溢、毛边和串色。无损版验证像素等价，有损版检查 alpha、轮廓和颜色观感。
2. **连续播放对比。** 至少看起手、峰值、收招和循环接缝，检查逐帧静图中不易发现的闪烁、细线跳变与色阶抖动。确认脚底、挂点和最终可见体型稳定。
3. **新进程只挂载 PCK。** 验证动态依赖、动画名、帧数、逐帧时长和透明纹理可加载。测试正常、快速、瞬时、连续重播、受击打断及相应的死亡与复活。分别记录源视频时长、释放标记、命令等待和实际播放时长。
4. **用正式流程出包。** 先用 [export_guardian_mod.ps1](../tools/export_guardian_mod.ps1) 的 `-SkipInstall` 构建验证包，再用目标版本实战验收。记录每个动作的压缩模式、质量、前后字节数、画质结论，以及整包大小、首载时间和峰值内存。将正式资源路径和必要的参数更新到对应角色的 `manifest.json` 与 `checklist.md`。

## 5. 已有实测基准

在 `animate-0.1` 的隔离副本中用 Godot 4.7.2 测得。正式导出脚本默认使用 Godot .NET 4.5.1，以下数据作为选型和复测基准。

| 测项 | 原始 | 测试结果 |
|---|---:|---:|
| 当前 PCK，排除尚未接入的交付素材、预览和候选资源 | 878.2 MiB | 516.8 MiB |
| 31 个动画 `.res`，仅换成质量 0.85 的纹理编码 | 313.9 MiB | 66.0 MiB |
| 女爵篝火待机，保留 190 帧 | 51.0 MiB | 10.1 MiB |
| 复仇者篝火待机 | 35.6 MiB | 4.5 MiB |
| 塞巴斯蒂安咆哮 | 26.8 MiB | 4.9 MiB |
| 守护者战斗待机 | 19.7 MiB | 2.5 MiB |
| 女爵重演人物和表盘两层，压缩并移除弃用短版 | 16.2 MiB | 3.6 MiB |

基线包中测得约 150.3 MiB 的新旧路径重复资源。过滤测试包通过铁之眼现有 23 项动画检查，压缩后的资源通过独立重载和时间线校验。表中 PCK 和动画资源的体积属于不同统计范围。正式接入后的整包大小与实战画质以目标版本复测为准。

## 6. 2026-11-22 最终压缩结果

- 战斗/非篝火资源 **36 个 `.res`**：使用 `PortableCompressedTexture2D` **LOSSLESS**，保留原分辨率、帧数和逐帧时长。
  - 373.1MB → **203.4MB**。
  - 抽检 `combat_idle`、`death`、`time_command`、`ironeye_sequences`、`idle_pursuit`：逐帧 RGBA **0 diffs / exact**。
- 篝火资源 **3 个**：有损 q=0.85 + 15FPS 时间重采样（不改像素尺寸）。
  - Guardian 51.1→3.42MB（75帧/7页）
  - Duchess 51.0→6.48MB（119帧/10页）
  - Revenant 35.6→2.81MB（67帧/5页）
- 最终全部动画 `.res`：**216.1MB / 1834.9MB 估算 VRAM**（全部动作同时常驻；实际应按场景/动作加载）。
- 原始备份：`.tmp/animation_compression/backup/`。
- 无损批量报告：`animations/animation-compression-lossless-batch.json`；旧有损测试报告：`animations/animation-compression-lossy-test.json`；篝火报告：`animations/camp-lowfps-report.json`。
- 预览已排除出 PCK；压缩不降低 VRAM，加载优化仍需按场景/动作懒加载。
